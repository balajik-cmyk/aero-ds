# Tabs

Tabs organise related content into multiple panels, showing one at a time. The active tab's panel is visible; others are hidden.

---

## Usage

### When to use

- **Related content** that users need to switch between without leaving the page.
- **Categorised views** — e.g., "Overview / Responses / Analytics" in a Reviews page.

### When not to use

- **Sequential steps** — use `Stepper` instead.
- **Page navigation** — use the app sidebar or breadcrumb.
- **Filtering** — use `Chip` or `Select`.

### Limits

- **2–7 tabs** per row. More tabs become hard to scan.
- All tab labels should be **comparable in length** — avoid mixing "Overview" with "Detailed performance breakdown".
- Do not nest tabs within tabs.

---

## Content guidelines

- Tab labels: **1–3 words**, noun or noun phrase — "Examples", "Usage", "Accessibility".
- Sentence case, no punctuation.
- Labels should clearly describe the panel content.

---

## Behaviour

- Active tab: bold label + 2px `var(--primary)` bottom underline.
- Hover: grey pill background on the tab label.
- Tab panels are lazy-rendered (Radix default) — content mounts on first activation.
