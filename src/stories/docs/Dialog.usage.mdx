# Dialog

A dialog displays content in a modal overlay, requiring the user to interact before returning to the page.

---

## Parts

1. **Overlay** — semi-transparent backdrop behind the dialog.
2. **Container** — the dialog surface, centered by default.
3. **Header** — title (required) and optional description.
4. **Body** — main content area.
5. **Footer** — action buttons (primary + secondary/cancel).
6. **Close button** — always present (`DialogClose`).

---

## Usage

### When to use

- **Confirmation** — "Are you sure you want to delete this agent?"
- **Short forms** — login, quick create, settings that don't warrant a full page.
- **Interruptions** — errors or critical info that must be acknowledged.

### When not to use

- **Complex workflows** with many steps — use a full page or `Stepper`.
- **Contextual details** about a selected item — use `Drawer` instead.
- **Informational hints** on hover — use `Tooltip` or `Popover`.

### Sizes

| Class | Max-width | Use for |
|---|---|---|
| `max-w-sm` | 24rem | Simple confirmations |
| `max-w-lg` | 32rem (default) | Standard forms |
| `max-w-2xl` | 42rem | Forms with more fields |
| `max-w-4xl` | 56rem | Rich content, preview |

---

## Content guidelines

- **Title**: concise noun phrase or question — "Delete agent?", "Create review request".
- **Description**: 1–2 sentences explaining what will happen.
- **Primary action**: matches the title — "Delete", "Create", "Confirm".
- **Cancel**: always labelled "Cancel", never "No" or "Close".
- Destructive dialogs: primary button uses `variant="destructive"`.
